# 生产入口由单一发布清单生成

日期：2026-08-30 · 状态：Accepted

## 背景

`index.html` 与 `index-v5.html` 已经演化为内容完全相同的生产入口，各自手工维护 49 个有顺序依赖的 `<script>` 标签。V5.1 发布期间，脚本缓存指纹、页面加载顺序和测试断言分散在两份 HTML、发布检查与多组测试中；一次缓存修复因此需要连续修改多个位置，默认 `npm test` 又只覆盖 70 项测试，未能发现完整测试中的加载断言漂移。

## 决定

1. `index.html` 是生产页面内容的唯一可编辑来源；`index-v5.html` 保留原网址和相同行为，但只作为 `index.html` 的生成镜像，不再手工编辑。
2. `scripts/production-release.mjs` 是生产脚本顺序、发布身份与缓存策略的唯一权威。它只生成两份静态 HTML 中带标记的运行时区块，不引入 bundler，也不在浏览器中动态装载脚本。
3. 第一方运行时资源共享同一个生产发布身份；固定的 vendored 资源保留稳定 URL。发布检查从同一清单解析应部署的资源地址，不再维护独立版本字符串。
4. `npm run sync:production-entry` 更新生产入口与镜像；`npm run check:production-entry` 对发布身份、脚本顺序和镜像一致性执行失败关闭校验。
5. 默认 `npm test` 运行 `tests/*.mjs` 完整测试集，加载图和发布装配测试不再位于默认验证范围之外。

## 取舍

- 不使用运行时 JavaScript 逐个注入依赖，因为这会改变浏览器预加载与执行时序。
- 不引入构建工具或模块打包器；提交到仓库的两份入口仍是 GitHub Pages、桌面模式与本地静态服务可直接使用的普通 HTML。
- 不把 `index-v5.html` 改为跳转页，避免破坏既有书签、桌面入口和相对路径行为。
- 本决定只收口网页发布装配，不改变 Paper Import、Map Integration 或地图库的业务行为。

## 后果

- 新增、删除或重排生产脚本只修改发布清单并重新同步一次。
- 修改生产页面正文只编辑 `index.html`，随后同步镜像；漂移会被项目命令和完整测试阻止。
- 更新第一方运行时后必须推进发布身份并重新同步，否则发布检查会拒绝不一致的入口。
- 两份 HTML 仍会在仓库中物理存在，但它们不再形成两个维护权威。
